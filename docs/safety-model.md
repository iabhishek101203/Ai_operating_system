# Safety Model

## Non-Negotiable Rule

The assistant must never execute arbitrary shell commands generated by an LLM.

LLM output is treated as untrusted input. It must be parsed into a known schema, validated against policy, previewed for the user, and executed only through approved Python tool implementations.

## Threats

- Prompt injection that asks the model to bypass validation.
- Path traversal outside allowed directories.
- Destructive operations without confirmation.
- Confused deputy behavior where the assistant acts with more authority than intended.
- Ambiguous natural language leading to unexpected filesystem changes.
- Incomplete logging that prevents investigation or recovery.

## Defensive Controls

- Use function calling with strict schemas.
- Validate all paths with `pathlib.Path.resolve`.
- Restrict operations to configured workspace roots.
- Provide dry-run previews for every operation.
- Require explicit user confirmation for mutating operations.
- Execute only allowlisted tool classes.
- Log operation input, preview, result, timestamp, and undo metadata.
- Prefer reversible deletion through trash APIs over permanent deletion.

## Operation Risk Levels

```text
read_only      Search, inspect, list files.
reversible     Rename, move, copy, send to trash.
destructive    Permanent delete or overwrite. Avoid in early milestones.
external       Network, browser, package managers, project generators.
```

## Early Policy

Milestone 1 allows only read-only filesystem search. Mutating operations will be added after the validation, preview, logging, and undo contracts are stable.
